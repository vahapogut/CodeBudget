# Actual client MCP smoke without a model

Run `pnpm build`, then `node scripts/smoke-clients.mjs` with an installed Codex CLI. The result is saved to [client-smoke-result.json](client-smoke-result.json). This check has no paid model connector and starts no conversation or turn.

On Windows with Node 22.16.0 and Codex CLI 0.139.0, the actual Codex app-server connected to CodeBudget and discovered the `get_changes`, `prepare_context` and `read_evidence` tool schemas. Server metadata identified `codebudget` version `0.1.0-beta.1`. The local stdio server requires no account authentication; the client's `authStatus: unsupported` means this transport has no OAuth authentication mechanism, not a failed connection.

The script creates a temporary project and a separate temporary `CODEX_HOME` for child processes. It runs the built CodeBudget CLI's observe-mode initialization and project-local Codex adapter installation, trusts only that temporary project, and disables analytics/feedback in the temporary client configuration. Only operating-system process variables are inherited; existing account credentials and user client configuration are not supplied. The parent environment and global settings are unchanged. Temporary files and the app-server are cleaned up after the check.

Before connecting, the installed client generates its own protocol JSON Schema. The script checks that its two request methods are supported, then sends exactly `initialize`, the `initialized` notification, and `mcpServerStatus/list`. It verifies the live inventory and each tool's object input schema. It sends no `thread/start`, `turn/start`, account or login request. A Codex warning about declining to create PATH helper aliases under the temporary directory is retained with normalized paths; that warning did not prevent the connection.

This proves the installed Codex client's project registration and MCP inventory handshake. The script does not call the tools through Codex, execute a model session, measure client prompt replacement, capture provider usage, or establish task quality or token savings. Tool execution itself is covered separately by the MCP SDK and installed-package protocol smoke tests. Claude's actual-client health check, and actual Cursor/Antigravity clients, are outside this script's measured coverage. Reference-solution task tests remain local evaluator checks; real-model pilot experiments remain unrun.
