## Usage import correction (2026-09-30)

Pinned Codex 0.139.0 source shows that the exec JSON processor fills `turn.completed.usage` from `ThreadTokenUsage.total` and emits `Usage::default()` when no token count arrived. The session seeds that total from the rollout on resume and fork, and `fill_to_context_window` replaces it (per-field counts zero) when the context window is reported full. Importer 1.1.0 treated it as a per-turn delta and over-counted resumed threads, re-imports and repeated lines. Importer 1.2.0 stores cumulative observations per hashed thread, treats all-zero usage and visible restarts as unknown, and excludes importer 1.1.0 Codex records from totals until they are re-imported. Claude OTLP JSON Lines captures are accepted. These are contract fixtures from pinned source, not a real client capture.
