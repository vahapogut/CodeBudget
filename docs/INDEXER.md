# Repository index and context packages

`packages/indexer` is an offline TypeScript/JavaScript syntax index, FTS5 search engine, working-tree snapshot service and context budget selector. It does not execute repository scripts or resolve a TypeScript type graph.

```ts
const indexer = await createIndexer(root, dataDir, {
  redact: coreRedactor,
  securityPolicyId: 'core-redaction-v1',
  dependencies: { maxDepth: 2, maxFiles: 64 },
  tokenizerConfig: { encoding: 'o200k_base', model: 'gpt-4o' },
});
await indexer.index();                       // optional; prepareContext refreshes the index first
const context = await indexer.prepareContext({
  task: 'Fix refresh token rotation', budget: 8000,
  sessionId: 'session-id', epoch: 'context-epoch',
  requiredPaths: ['src/auth.ts'],
  acceptanceCriteria: ['The existing refresh-token regression test passes'],
  constraints: ['Preserve the public API'],
});
indexer.readEvidence(context.sources[0].evidenceId, { sessionId: 'session-id', offset: 0, limit: 200 });
const before = indexer.getChanges(undefined, 'session-id');
const after = indexer.getChanges(before.snapshotId, 'session-id');
await indexer.rebuild();                     // drop and recreate this derived database, then index again
indexer.close();
```

`since` accepts a snapshot ID returned by this service (`getChanges` or `index`), not an arbitrary Git ref. Snapshots compare saved, eligible working-tree file hashes and include untracked files. Identical-content moves are inferred as renames: each added path is paired with the lexicographically first deleted path of the same content, using one hash map. Modified moves are an addition and a deletion. Unsaved editor buffers are unavailable. The real repository/worktree path identifies the database. Snapshots, evidence and expansion chains reject another session's identifier.

## Storage

The database is `index-<cache-id>.sqlite` inside the configured data directory, which is created as a private (0700) directory containing a `.gitignore` of `*`, so it never becomes visible to Git even without a root rule. The cache identity keeps the original 24-character form; on Windows it hashes the lower-cased root like the public repository ID, and a cleanly closed file with the earlier case-preserving name is adopted once. Public repository IDs use the same full normalized-root SHA-256 as core. The database uses WAL, a five-second busy timeout, cached prepared statements and explicit transactions. Linked data directories and database files are rejected.

Schema 3 stores no source bodies. Each file row holds its path, full content hash, stat identity, per-file cache version and compact metadata: top-level symbols (name, kind, lines, UTF-16 offsets, byte size, exported flag and the same-file type declarations each symbol references) and redacted import statements. Search uses a contentless FTS5 table (`contentless_delete=1`) whose rows share the file row ID: the `content` column indexes the redacted source, the `symbols` column indexes name words (file stem and symbol names). Replacing a file's search row is therefore an indexed rowid delete, and source bodies exist in the database only as index terms. Bodies are read from disk when a context is prepared, verified against the indexed hash and redacted again with the current policy.

Migration to schema 3 keeps file identities (so existing evidence stays verifiable), converts snapshots into deduplicated compressed contents, reduces stored packages to their accounting metadata and evidence references, and marks file metadata for reparsing by the next index. Schema 1 retention columns are added first. Corrupt databases and unsupported future schema versions fail explicitly; no automatic destructive recovery is attempted. This is a rebuildable index, not the authoritative source of code: `rebuild()` drops and recreates every derived table in place (safe while other connections are open), compacts the file and indexes again. Existing evidence IDs, snapshots and expansion chains are then invalid.

Indexing compares each file's stat identity (size, modification time, change time and inode) with the stored row and does not re-read unchanged files. Like Git's racy-clean rule, a file modified within three seconds of being read is re-read on the next pass. Changed files are read, parsed and redacted outside any write transaction and committed in batches (256 files or 8 MiB), so a second process waits at most one batch for the write lock, and an interrupted or cancelled run keeps its committed batches; the next call resumes. `index({ signal })` checks an `AbortSignal` between files. Each stored row matches the content that was read; an edit made later is detected by its stat identity. A torn read (the file changed while being read) is retried twice; a file that keeps changing is reported as `changed_during_indexing` and keeps its previous row. Concurrent instances in one process serialize indexing; SQLite arbitrates separate processes. The opened source inode is checked with bigint identities. Windows `lstat.dev` can be zero, so a zero device field is not compared against `fstat`'s volume serial.

## Source boundary

Exclusions use core's shared repository path policy: secrets, credential files and key material, dependency and tool caches (`node_modules`, `.git`, `.venv`, `.cache`, ...) and CodeBudget local state anywhere; generated output directories (`dist`, `build`, `coverage`, `vendor`, ...) only at the repository root or directly beside a package manifest, so source folders such as `src/build` stay visible. SQLite database and journal files are excluded as data. These hard exclusions cannot be negated by ignore rules. The configured data directory is also excluded.

Ignore sources apply with Git precedence, lowest first: `core.excludesFile` (repository `.git/config`, then the global Git configuration, default `$XDG_CONFIG_HOME/git/ignore`), `$GIT_DIR/info/exclude` (linked worktrees use the common directory), then root and nested `.gitignore` and `.codebudgetignore` files. Git metadata is found through the root's own `.git` directory or `gitdir:` file; ignore files above the root are not read. Configuration is read as data; include directives are not followed and nothing is executed. Patterns match case-insensitively when `core.ignorecase` is true or, if it is unset, when the file system is case-insensitive (probed on the data directory). Ignore files are decoded leniently like Git's byte-oriented parser, so a Latin-1 comment does not fail. A symlinked ignore file is read through the link as patterns only; its content can only change which files are excluded and is never emitted. When a `.gitignore` or `.codebudgetignore` file cannot be read, its directory is not indexed (fail closed), rows indexed there earlier are kept, and the problem is reported; an unreadable `.git/config`, `info/exclude` or `core.excludesFile` is reported and skipped, as Git does.

Every exclusion is visible in `IndexResult.skipped` (and the first 20 in `doctor` warnings) with a stable reason and a repository-relative path: `secret`, `dependency`, `local_state`, `generated_output`, `data_file`, `ignored`, `symlink`, `file_count_limit`, `total_source_bytes_limit`, `file_size_limit`, `binary`, `invalid_utf8`, `not_regular_file`, `changed_during_indexing`, `parse_failed`, `unsupported_path`, `ignore_rules_unreadable[:<code>]` or `unreadable[:<errno code>]`; a race with a concurrent change can also report `symlink`, `outside_repository` or `excluded`. Reasons never contain absolute paths. Files with unsupported extensions are not sources and are not listed. On POSIX a backslash in a file name is an ordinary character, never a separator.

Symlinks and directory junctions are skipped; every source read validates repository containment, refuses linked path components, opens with `O_NOFOLLOW` and re-checks the opened identity. Traversal and absolute POSIX/Windows/UNC paths are rejected. Only supported text extensions are read, with fatal UTF-8 decoding and binary detection. Defaults are 1 MiB per file, 64 MiB total source bytes and 20,000 files. The file-count and byte limits are allocated fairly: directories are interleaved round-robin at every level, so a large directory cannot starve a small one. When limits skip files, context packages warn, and a task that names a skipped source reports it in `missingRequired`.

A custom security policy ID participates in invalidation through the per-file cache version (parser, storage format and policy). An unversioned injected redactor is trusted for one indexer instance only, so each new instance reparses. Redaction failures abort delivery. Detectors are defense in depth, not a promise that every secret is recognized. `doctor` reports `current: false` when content changed or when the cache version differs from the current configuration.

Evidence reads require the source to be still indexed and still eligible under the current exclusions and ignore rules (checked along its directories, before any re-index), then validate the current source hash and apply full-source redaction before pagination; multiline redaction that changes line layout returns a safe explanatory placeholder rather than a misleading page.

## Parsing and ranking

Runtime: `web-tree-sitter@0.27.0`; official grammar packages: `tree-sitter-javascript@0.25.0`, `tree-sitter-typescript@0.23.2`. Their shipped WASM files support JS, JSX, TS and TSX with no runtime network. On 2026-09-29, a direct Node 22.16.0 parse of all three grammars passed. `tree-sitter-wasms@0.1.13` failed the current loader's dynamic-link format and was replaced, not silently treated as semantic support.

Official references checked: [Tree-sitter WebAssembly binding instructions](https://github.com/tree-sitter/tree-sitter/blob/master/lib/binding_web/README.md), [Node SQLite](https://nodejs.org/api/sqlite.html), [SQLite FTS5](https://www.sqlite.org/fts5.html). The FTS5 website fetch was unavailable during this session; an actual SQLite 3.49.1 FTS5 create/query smoke test validated runtime availability. Contentless tables with `contentless_delete=1` require SQLite 3.43 or newer; Node 22.22.2 bundles SQLite 3.51.2. Registry versions and package WASM contents were checked with `npm view` and `npm pack --dry-run`.

Stored top-level functions, classes, variables and type declarations retain source offsets and lines; bodies are sliced from the verified source when selected. Imports/exports have syntax-level references found by the parser's native descendant search; dynamic `import()`/`require()` calls are searched only when the text can contain such a call. Relative import resolution, dynamic calls and associated tests are explicitly heuristic. Incomplete syntax is retained with `parseErrors`; other supported text files have `text_fallback`. No semantic support is claimed for other languages.

Selection combines name words, explicit locations, FTS5 matches, bounded transitive imports and related test candidates. Defaults: name 12, text 4, location 30, dependency 6, test 5. These are configurable ranking weights, not calibrated probabilities. Name words come from the file name and symbol names (NFC, camelCase, digit and `_` splits); directory names never seed relevance, except the directory of a module entry file such as `src/auth/index.ts`. File extensions alone never seed relevance. Task words are quoted FTS5 phrases: text matches rank the `content` column for the first 30 task words (top 300 by bm25), and the `symbols` column, queried with all task words, only preselects files whose exact name hits are then counted. Related tests share the exact file stem (`auth.ts` and `auth.test.ts`), never a substring.

Explicit required paths, and indexed paths named in the task, are mandatory. A task names a path only as a whole NFC path at token boundaries: `data.ts` does not name `a.ts`, `src/index.ts` does not name `index.ts`, while `./src/app.ts`, `@src/app.ts`, `src/app.ts:42` and a trailing full stop do. Required missing, ignored or skipped sources are reported. Optional sources sort by score per estimated token cost with stable path/line tie-breaking; the cost includes the referenced type declarations that accompany a body. A selected symbol carries only the interface, type alias and enum declarations of its file that it references (transitively), each at most once per package, and the first selected symbol of a file carries the file's static imports; whole-file sources carry neither, because their body contains them. `redacted` marks a source whose delivered code was changed by redaction.

Static relative imports and re-exports expand breadth-first from explicit/name-matched sources, default depth 2 and at most 64 additional files. Each selected dependency carries a root, the complete file path chain, depth and `relative_static_heuristic` label. Shortest paths win; ties use stable path ordering. A file receives the dependency weight once, divided by depth. Cycles cannot inflate scores. `contextDependencies` in `.codebudget.json` controls `maxDepth` (0–8) and `maxFiles` (0–512); zero disables expansion. Roots remain separately eligible for ordinary selection. Expansion makes dependencies candidates, not mandatory inclusions.

Resolution uses only safely indexed files. An existing explicit code filename wins. A missing `.js`/`.jsx`/`.mjs`/`.cjs` filename may map to its sole corresponding TS/TSX/MTS/CTS source. Only a supported code extension counts as an extension, so dotted names such as `./user.service`, `./app.component` or `./config.dev` are extensionless: they check supported code extensions and directory `index` files. Multiple candidates are reported as ambiguous and never guessed. Dynamic import/require, malformed importer syntax, unresolved paths, unsupported query/escaped specifiers, root escapes and depth/file limits appear in `dependencyExpansion.issues` (20 details plus omitted count). Bare package names and aliases are excluded; there is no tsconfig, package-exports, bundler, runtime or type resolver. Final validation checks every included chain's intermediate hashes, even when an intermediate body was omitted for budget. Changed paths withhold the whole stale package; an optional candidate whose file changed after indexing is omitted with a warning instead.

## Budget and expansion

The entire serialized package is measured, including paths, reasons, warnings, dependency provenance, omitted references, constraints and token metadata. `protocol: 'mcp_text'` includes the controlled MCP content/text result envelope and JSON escaping; JSON-RPC transport framing and hidden client/provider context remain outside this measurement. The default estimator is `ceil(UTF-8 bytes / 2)`; it identifies itself as estimated, model unknown, without a provider budget guarantee, and it is **not an upper bound**: dense text such as base64 or hex can need more tokens under a real BPE encoding.

`js-tiktoken@1.0.21` provides opt-in **exact local** BPE with shipped `o200k_base` and `cl100k_base` rank tables. Only the lite encoder and those two tables are bundled; encoding/counting makes no model or network call. Configure `.codebudget.json` with `"contextTokenizer": { "encoding": "o200k_base", "model": "gpt-4o" }`, or use `codebudget context --task "Fix auth" --tokenizer o200k_base --model gpt-4o`. Omitting `model` counts the chosen encoding exactly without asserting a model mapping. Both CLI and MCP workers apply project configuration. The async library factory accepts `tokenizerConfig`; direct constructor callers can inject a ready `Tokenizer` instead.

The explicit model-label allowlist is `gpt-4o`, `gpt-4o-mini`, `gpt-4.1`, `gpt-5`, `o1`, `o3`, `o4-mini` for `o200k_base`, and `gpt-4`, `gpt-3.5-turbo` for `cl100k_base`. A contradictory known pair fails. Unverified labels, including unlisted dated/future aliases, fall back to the byte estimate with `modelMapping: unknown` and a visible `fallbackReason`; there is no prefix guessing. Metadata identifies encoding, model, tokenizer version, method and `exact_local`/`estimated` accuracy. `guaranteed: true` refers only to the exact stated serialized-text scope, never provider usage, conversation framing, quotas or billing. Source strings such as `<|endoftext|>` count as ordinary text, not special tokens. Imported provider usage remains separate.

The finite model mapping was checked against [OpenAI's tiktoken mapping](https://github.com/openai/tiktoken/blob/main/tiktoken/model.py). English, arithmetic and Japanese regression counts use the [official token-counting cookbook](https://developers.openai.com/cookbook/examples/how_to_count_tokens_with_tiktoken). Local loading follows the [js-tiktoken lite API](https://github.com/dqbd/tiktoken/blob/main/js/README.md). Tables are cached per process. Selection accounts incrementally: each candidate's serialized entry is counted once when it is considered, candidates are read and tokenized only when a size estimate calibrated on earlier entries says they can still fit, and selection stops when not even an empty entry fits. The final serialization is then recounted exactly; if boundary effects or metadata push it over the budget, the lowest-ranked optional sources are evicted and it is counted again. Count metadata converges by recounting the final serialization, up to 20 iterations. A tokenizer whose self-referential count does not converge raises an error rather than returning a false exact count.

Mandatory source bodies are never silently cut. If required content or the minimum metadata envelope is too large, status is `budget_exceeded` with `minimumRequiredTokens`, retained mandatory content and an expansion warning. Optional omissions are counted in `omittedCount`, trigger a warning, and have up to 20 detail references when those references fit. A changed source during final validation produces `snapshot_inconsistent` and withholds stale excerpts.

Pass `previousPackageId` to track expansion count and cumulative package tokens. Session/epoch or tokenizer identity changes reject the chain to prevent adding incompatible units. A new epoch or tokenizer starts a new chain. Selection policy, weights, dependency limits and tokenizer identity participate in package IDs. Every package resends chosen sources: the service never assumes that the client still remembers an earlier package.

## Verification

Focused indexer and tokenizer tests cover real WASM parsing, FTS5 selection, ignored/sensitive files, damaged syntax, Unicode paths, symlink junctions, traversal, source mutation, deletion/rename, concurrent connections, repository/session isolation, epoch resets, redaction/cache invalidation, envelope accounting, mandatory overflow, size limits, metadata retention and SQLite disk quota rollback. Import-graph tests cover transitive re-exports, JS-to-TS paths, dotted extensionless specifiers, cycles, ambiguity, depth/file bounds, deterministic provenance and changed intermediate files. Tokenizer tests check official golden counts, literal special-looking strings, model fallback, exact JSON/MCP envelope accounting and incompatible expansion rejection.

Regression tests (`regressions.test.ts`, `performance.test.ts`, `incremental.test.ts`) cover repeated contexts without per-call snapshots or stored source copies, snapshot deduplication and byte eviction, full-database recovery by pruning and one retry, `rebuild()` of an over-budget index, a 1/10-scale copy of the 5,000-file benchmark repository within the proportional budget, referenced-type attachment, visible exclusions with stable reasons, Git exclude sources and case-sensitive patterns, fair limit allocation, files rewritten during indexing, Latin-1/symlinked/unreadable ignore files, whole-path task matching with NFC and exact test stems, evidence revocation after new ignore rules, stale-cache doctor reports, FTS5 query syntax in tasks, schema 1 and 2 migrations, stat-identity change detection (source reads counted), lock release between batches, resumption after an aborted index, and complexity ratios with absolute caps for re-indexing, exact-tokenizer selection and long tasks. Separate CLI, MCP-worker and config tests verify the public configuration paths. Public repository identity is verified against core.

Local measurements on 2026-09-30 (Linux container, 4 CPUs under concurrent load, Node 22.22.2; not a benchmark of other machines): a generated 5,000-file, 33.6 MB TypeScript repository indexed in 18.6–20.9 s into a 19.7 MiB database within the default 32 MiB budget, an unchanged index took 266–283 ms, and context preparation took 1.0–1.3 s for broad tasks matching most files. Preparing context for 150 files × 10 functions with `o200k_base` took 0.12–0.19 s. The previous implementation failed that repository with a full database after 27 s and needed about 50 s for the 150-file selection.

Synchronous scanning and `node:sqlite` work should run in a worker when a caller requires enforceable timeout/cancellation. Cancellation cannot interrupt a synchronous filesystem operation or a batch in the same event loop; committed batches survive worker termination. No claims of live IDE verification or task-level savings follow from these tests.

## Retention and disk limits

`IndexerOptions` accepts `retentionDays` (default 14), `maxSnapshots` (1000), `maxPackages` (500), `maxEvidence` (10000), and `diskBudgetBytes` (32 MiB; the CLI and MCP server pass a quarter of the configured `diskBudgetBytes`, 128 MiB by default). Context preparation does not create snapshots; `getChanges` and `index` do, as small rows that share one compressed content row per distinct working-tree state (paths and 128-bit hash prefixes). Stored packages keep only token accounting, expansion metadata and evidence references, never source text.

Retention prunes by age, count and bytes on every snapshot or package admission: snapshots and packages (with the evidence rows they reference) may each use an eighth of the disk budget (at least 64 KiB), evicting the oldest first, and the newest row of each kind is always kept. Evidence referenced by retained packages is preserved; if the evidence count would exceed the cap, older packages are evicted with their orphan references. A single package larger than the evidence-reference cap is rejected explicitly. A reference from an evicted package is no longer valid. `prune(true)` previews IDs and row counts; `prune(false)` removes only snapshot/package/evidence metadata (and orphaned snapshot contents) and truncates the WAL when SQLite permits. Neither operation deletes source files or indexed source rows.

SQLite `max_page_count` bounds main-database growth. When a write finds the database full, retention runs again with budgets sixteen times smaller and the write is retried once; if it still fails, the transaction rolls back and the error names `diskBudgetBytes` and the remedies (raise the budget, exclude generated sources, rebuild). An existing database larger than a reduced budget opens; free pages are compacted, and if the index itself still exceeds the budget, indexing fails with a message naming `diskBudgetBytes` and `rebuild()`. Deleting rows makes pages reusable; it does not promise immediate physical database shrinkage. Automatic checkpoints and `journal_size_limit` bound normal retained journal size, but an active transaction or another reader can temporarily retain WAL pages above that target. Thus `diskBudgetBytes` is a main-database page quota, not a strict aggregate filesystem hard cap. The caller should allocate this index quota separately from the artifact store.
